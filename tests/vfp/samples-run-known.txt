# What each form Visual FoxPro ships with says while it opens, one line per complaint.
#
# `tests/vfp/samplesRun.test.ts` opens every .scx under the Samples\Solution folder with
# DO FORM ... NOSHOW and fails on any line that is not here. Run it with RUN_REPORT=<file> to
# write the list again. It only shrinks.
#
# It used to be 236 lines, 190 of them one complaint: a form's data environment could not find
# its table, and then everything that needed that table failed after it. None of that was the
# product's. Measured against the forms themselves: vfp9.exe opens Controls\Checkbox\checkbox
# with the default directory anywhere you care to put it - the Solution folder, the form's own
# folder, the Samples folder - and PRODUCTS is open every time on
# c:\...\samples\data\products.dbf, because a data environment's Database is made absolute
# against the form file as the form loads. The earlier probe that said the product opened no
# table had been looking in the wrong data session: a form with DataSession 2 opens its tables
# in its own, and the default one stays empty. So all 190 were ours, and nearly all of them came
# of two things the harness did that the product does not:
#
#   - its in-memory file service matched a name letter for letter where Windows does not, so
#     `..\..\..\data\testdata.dbc` missed the `Data` folder it names;
#   - it seeded the Solution folder and the Data folder beside it and nothing else, and answered
#     HOME() with the project folder, where a sample started from the launcher has the whole
#     Samples folder around it and a HOME() that says where Visual FoxPro is installed.
#
# Several more used to be here for the same reason rather than because the runtime was at fault:
# the harness knew only the form under test, so a form that opened another one or installed a
# menu had nothing to open, and it gave the runtime neither the native library service nor COM.
# It now seeds every .scx and .mnx the samples ship and hands the runtime the same two
# main-process services the application hands the renderer, so what those forms say is the
# product's answer rather than the harness's.
#
# What is left is what the list is for: a member that is not there, a class that will not build,
# an Init that refuses. Measured as well - vfp9.exe opens every one of these forms and says
# nothing at all while it does.
#
# Every line below that is not a table says why it is here.
#
#   COM - an ActiveX control, or a class out of a type library. The bridge is real and a test
#   run gets it too, so a class this machine can make is made: Scripting.FileSystemObject
#   answers, and so does WMPlayer.OCX, whose cdromCollection counts the drives on this machine
#   and finds none. What the forms below want cannot be made here at all, and the reason is not
#   in this runtime: mscomctl.ocx, richtx32.ocx, mci32.ocx, shdocvw.dll and MSChart each
#   register their InProcServer32 only under Wow6432Node, so a 64-bit process gets
#   REGDB_E_CLASSNOTREG while 32-bit vfp9.exe opens every one of these forms without a word.
#   `docs/not-supported.md` says what would fix it. An OLE control the form names by its file
#   rather than by a ProgID - `(mci32.ocx)` - has no name to ask COM for either.
#
#   A flattened class - the importer builds a control from a class library by folding the class
#   into the base class underneath it. What is lost is the lineage: the object answers the base
#   class for `Class`, nothing for `ClassLibrary`, and `DODEFAULT()` finds no method above its
#   own. Class code that builds another object of its own kind, or that leans on its parent's
#   Init, has nothing to work with.
#
#   Refused on purpose - three of the lines below are not a gap at all. Microsoft Agent, the
#   Windows Messenger automation class and the Multimedia MCI control are named in
#   `docs/not-supported.md` and refused by name with their reason, so that the Output window
#   tells a developer "this will never work, and here is why" rather than "class not found".
#   Those three lines are not going to come off; the score is the lines that are not listed
#   there.
